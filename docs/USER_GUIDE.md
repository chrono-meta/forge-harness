# forge-harness 사용 가이드

**한 줄로**: FH 는 Claude Code 용 **메타하네스**다 — 프로젝트에 필요한 규칙 · 게이트 · 기억(= 하네스)과 스킬을 짓도록 돕고, 내보내기 전에 검증한다.
(하네스 = AI 에이전트가 같은 지시를 매번 다시 듣지 않도록 프로젝트에 둘러놓은 규칙 · 차단 장치 · 기록.)

**이 가이드를 끝내면 얻는 것**: ① FH 를 깔고 첫 인사에 메뉴가 뜬다 ② 내 프로젝트 하나를 매핑해 `tracks/` 가 생긴다 ③ 진단 또는 가속 요청 한 번으로 «순위 매긴 할 일 목록»을 받는다 (자동으로 고치지는 않는다).

**첫 세션 경로**
```
1. 설치       claude plugin marketplace add https://github.com/chrono-meta/forge-harness.git
              claude plugin install -s user fh-meta@forge-harness
              git clone https://github.com/chrono-meta/forge-harness.git ~/projects/forge-harness
2. 열기       cd ~/projects/forge-harness && claude
3. 인사       "안녕"  → 새 설치면 메뉴: 첫 프로젝트 만들기 · 기존 프로젝트 매핑 · 가이드
4. 매핑       "프로젝트 매핑해줘"  → ../ 의 git 레포를 찾아 tracks/{프로젝트}/ 생성
5. 첫 성과    "이 프로젝트 가속화해줘" 또는 "/context-doctor"
```
설치 없이 게이트만 써보려면 `npx --package @chrono-meta/fh-gate fh-gate` 한 줄이면 된다(Claude Code 세션은 불필요, Node 와 `claude` 또는 `codex` CLI 는 필요). 효과가 쌓이는 쪽(세션 기록 이어받기)은 **두 번째 세션부터** 보이니 첫날 판단하지 마라.

---

> **이 문서는 '읽는' 문서다.** 명령을 찾으려면 `CHEATSHEET.md`, 과거 작업을 찾으려면
> `CATALOG.md`, FH 가 무엇이고 왜 작동하는지는 `README.md` 를 봐라. 여기는 **처음 쓰는 사람이
> 첫 세션을 완주하는 것**, 그리고 **거버너 고르기**(§4)만 다룬다.

## 0. 먼저 — 지금 내 상태가 무엇인가

> 🗺️ FH 가 **무엇이고 · 어떻게 구현돼 있고 · 왜 믿을 만한지**를 한 장으로 먼저 보려면 [`docs/map/FH_MAP.md`](map/FH_MAP.md)
> (인터랙티브 그림: https://chrono-meta.github.io/forge-harness/). 이 가이드는 그 다음 «첫 세션 완주」다.

FH 는 세 가지 상태로 쓸 수 있고, **되는 일이 다르다.** 아래를 그대로 실행해서 확인해라.

```bash
ls CLAUDE.md knowledge/ plugins/ 2>/dev/null   # 있으면 → 클론했다 (A/B)
claude plugin list | grep fh-meta              # 있으면 → 플러그인이 깔렸다
ls tracks/ 2>/dev/null                         # 디렉토리가 있으면 → 프로젝트가 매핑돼 있다
```

| 상태 | 무엇이 되나 | 무엇이 안 되나 |
|---|---|---|
| **클론 + 플러그인** | 전부 | — |
| **클론만** | 규칙·지식·게이트(훅) | 슬래시 커맨드(`/harness-doctor` 등) |
| **플러그인만** | 스킬 호출 | `knowledge/` 정본, 세션 기록(`tracks/`), 자체 게이트 |

셋 다 아니면 `README.md` 의 설치 절을 먼저 보고 오면 된다.
확신이 안 서면 **`/install-doctor`** 를 부르면 기계가 대신 판정해준다.

## 1. 첫 세션 — 실제로 무엇을 타이핑하나

**'안녕' 한 마디면 된다.** 인사가 온보딩 트리거다(어느 언어든).

```
당신: 안녕
FH  : 🐿️  Welcome to FH. ① 첫 프로젝트 만들기 · ② 기존 프로젝트 매핑 …
```

인사 뒤에 뜨는 이 선택지 목록 전체를 **메뉴**, 그 안의 선택지 하나하나(①②③…)를 **문**이라 부른다.
**매핑**은 FH 가 내 레포를 알게 하는 일이다 — «연결해줘» 라고 말해도 같은 일이 일어난다.

메뉴가 뜨면 **문 번호를 말하거나 그냥 하고 싶은 일을 문장으로 말하면 된다.** 문은 안내지 강제가 아니다.
바로 일을 시키고 싶으면 인사를 건너뛰고 작업을 말해도 된다 — 그러면 메뉴는 안 뜬다.

**문이 하는 일**

| 문 | 언제 고르나 |
|---|---|
| ① 프로젝트 매핑 | 이미 있는 레포를 FH 가 알게 한다. 여기서부터 대부분 시작한다 |
| ② 새 프로젝트 | 아직 없는 것을 처음부터 |
| ③ 가속/진단 | 매핑된 프로젝트에 대해 «개선해줘» · «진단해줘» |
| ④ 크로스 시너지 | 프로젝트가 2개 이상일 때만 뜬다 |
| 🔧 FH 자체 개발 | FH 를 고치는 사람에게만 뜬다 |
| 📖 가이드 · Q&A | 이 문서를 열거나, FH 사용법을 묻는다 |

## 2. 알아두면 헷갈리지 않는 것 넷

**ⓐ FH 는 '대신 해주는' 게 아니라 '틀리기 어렵게' 만든다.**
그래서 가끔 **막는다.** 커밋이 막히면 고장이 아니라 게이트가 일한 것이고, 화면에 **무엇을 하면
풀리는지**가 같이 뜬다. 그 문구를 그대로 따르면 된다.

**ⓑ '없음'과 '못 쟀음'을 구별해서 말한다.**
FH 는 확인 못 한 것을 0 으로 적지 않는다. `UNMEASURED` · `SKIPPED` · `못 쟀다` 같은 말이 보이면
**그건 실패가 아니라 정직한 공백**이다. 숫자가 안 나온 게 아니라 안 나왔다고 말하는 중이다.

**ⓒ 비가역한 일 앞에서는 반드시 멈춘다.**
공개 전환 · 삭제 · 히스토리 재작성. 되돌릴 수 있는 일(커밋 등)은 경고만 하고 넘어간다.
**이 둘의 차이가 FH 설계의 중심**이다.

**ⓓ 기록은 자동으로 쌓인다.**
`tracks/` 는 gitignored 라 공개 레포에 안 올라간다. 세션이 끝날 때 카드가 갱신되고,
다음 세션이 그걸 읽고 이어간다. '지난번에 뭐 했지'라고 물으면 거기서 찾아 답한다.

## 3. 자주 막히는 곳 (FAQ)

**Q. 커밋했는데 `🚫 BLOCKED` 가 뜬다.**
FH 자산(규칙·스킬·스크립트 등)을 고치면 4축 검증 마커를 요구한다. 화면에 **정확히 무엇을 어디에
쓰라고** 나온다. 우회(`--no-verify`)는 같은 훅에 있는 삭제 방지 게이트까지 같이 끄니 쓰지 마라.

**Q. 슬래시 커맨드가 안 먹는다.**
플러그인이 안 깔렸거나 옛 버전이다. `claude plugin list` 로 버전을 보고, 레포 `package.json` 의
버전과 다르면 `claude plugin update fh-meta@forge-harness` 후 재시작해라.
**등록됐다 ≠ 최신이다** — 이건 실제로 자주 난다.

**Q. 훅이 안 도는 것 같다.**
`git config core.hooksPath` 가 `templates/.git-hooks` 를 가리켜야 한다. 비어 있으면
`/install-wizard` 를 다시 돌려라(멱등이다).

**Q. 플러그인만 깔면 뭐가 없나?**
`knowledge/` 정본 · `tracks/` 세션 기록 · 이 레포 자체 게이트. 스킬은 돈다.

**Q. `tracks/` 는 왜 gitignored 인가?**
세션 기록엔 로컬 경로·프로젝트 이름 같은 개인 정보가 섞인다. 공개 레포에 안 올라가는 게 기본이고,
따로 보관하고 싶으면 개인 저장소를 붙이면 된다.

**Q. '진단해줘'와 '개선해줘'는 뭐가 다른가?**
같은 문이다(③). FH 가 기존 검사들을 모아 **M/S/R 로 등급 매긴 목록**을 주고, **자동으로 안 고친다.**
등급은 셋이다 — **M**(필수: 두면 기능이 깨지거나 데이터를 잃는다) · **S**(강력 권고: 두면 품질이 떨어지고 어긋남이 쌓인다) · **R**(권고: 고치면 효율이 좋아진다). 정의는 `knowledge/shared/GLOSSARY.md`.
무엇을 할지는 사람이 고른다.

**Q. 토큰이 너무 든다.**
`/context-doctor` 를 불러라. 무엇이 상주 중이고 무엇을 뺄 수 있는지 진단한다.

**Q. FH 를 떼고 싶다.**
FH 클론에서 `python3 scripts/fh_detach.py --project <마법사를 돌린 프로젝트>` — 먼저 무엇을 지울지 보여 주고 아무것도 안 바꾼다. 맞으면 `--apply`. 기본은 그 프로젝트만 뗀다 — 다른 프로젝트는 그대로다. 모든 프로젝트가 같이 쓰는 것(`~/.zshrc` 블록 · FH 클론의 훅 · `core.hooksPath`)까지 떼려면 `--machine` 을 더한다(안 주면 «kept (machine-wide …)» 로 보여 주기만 한다). 마법사를 돌린 다른 프로젝트는 그 프로젝트 경로로 따로 뗀다 — 그것들을 먼저 떼고 `--machine` 은 마지막에. 3.32.0 에서 바뀌었다: 그 전에는 `--apply` 만으로 공유분까지 지웠다. `--project` 로 FH 클론 자신을 주면 그 클론의 훅은 «그 프로젝트 것» 이라 `--machine` 없이도 지워진다. `--plugin` 은 fh-meta 플러그인과 forge-harness 마켓플레이스 등록까지 지운다. 클론 없이 플러그인만 깔았으면 `claude plugin uninstall fh-meta@forge-harness`.

## 4. 거버너 고르기 — 집약 · 감독

**거버너**는 일을 판단하는 세션이다(되돌릴 수 없는 곳을 막는 건 기계 = 게이트, 무엇을 원하는지는 사람 = 의도).
거버너를 두는 방법은 둘이고, 갈리는 건 **사람이 누구와 말하나**다. 정본 표:
`knowledge/shared/harness-core/governance_engineering_definition.md` §«누가 맡나». 이 절은 그 표를
**고르고 · 시작하고 · 이어가는 법**만 적는다. 개인 저장소나 다른 사람의 기억 없이, 클론 하나로 된다.

| | **집약** 거버너 | **감독** 거버너 («감사형» 이라고도 부른다) |
|---|---|---|
| 나는 누구와 말하나 | 거버너 하나와만 | 실무 세션들과 직접 |
| 거버너가 하는 일 | 서브에이전트를 띄우고 결과를 모아 한 창에 보여 준다 | 실무 세션들의 작업과 내 지시를 **위에서** 읽고 감사한다. 실무는 안 한다 |
| 이럴 때 고른다 | 한 덩어리 일 · 오늘 안에 끝남 · 볼 창이 하나면 좋겠다 | 여러 갈래를 내가 직접 끌고 감 · 며칠 이어짐 · 내가 시킨 일을 **저자가 아닌 눈**이 보길 원함 |
| 약한 곳 | 일을 시킨 쪽이 그 결과를 판정한다(독립성 약함) · 맥락이 금방 찬다 | 거버너가 하위 기록을 **실제로 열어 보지 않으면** 장식이 된다 · 한 박자 늦다 |

정본이 가르는 기준은 «사람이 누구와 말하나» 하나다. 위 «이럴 때» 줄은 그 기준을 고르는 데 쓰는 실용 권장이지 규칙이 아니다 —
헷갈리면 집약으로 시작하고, 내가 여러 세션과 직접 말하게 되면 그때 감독을 하나 띄우면 된다.

### 집약 — 시작하는 말과 필요한 것

```
이 일 네가 거버너로 맡아줘. 나눌 수 있는 건 서브에이전트로 돌리고, 결과는 모아서 보여 줘.
검증은 만든 에이전트 말고 다른 에이전트가 해.
```

- **런타임**: Claude Code 어디서든(CLI 포함) — 서브에이전트 기능만 있으면 된다.
- **위임할 때마다 묻는 게 정상이다.** FH 는 «묻지 말고 띄워도 된다» 는 기록이 없으면 위임마다 묻는다
  (`CLAUDE.md` §Agent Dispatch Operation). 안 묻게 하려면 프로젝트 루트의 **내 `CLAUDE.local.md`**
  (gitignored)에 아래 세 칸을 적는다 — 셋 중 하나라도 빠지면 계속 묻는다. 세션이 이 기록을 스스로 지어내거나
  늘리지 않는다 — 내가 답한 것만 적는다.

```
## 서브에이전트 위임 — 상시 요청
utterance   2026-11-15 "격리 위임은 묻지 말고 띄워"      ← 내 말 그대로
lease       2026-11-15 → 2026-12-15                     ← 끝나는 날 (날짜는 네 것으로)
scope       서브에이전트 위임만. 머지 · 발행 · 삭제는 포함 안 함
```

- **약한 곳 보완**: 중요한 산출물이면 마지막 판정만 다른 세션(또는 감독 거버너)에 맡겨라 — 일을 시킨 거버너는
  자기 지시를 감사하기 어렵다.

### 감독 — 시작하는 말과 필요한 것

거버너로 쓸 세션을 하나 열고:

```
너는 감독 거버너야. 실무는 내가 각 실무 세션에서 직접 할 거야.
너는 그 세션들의 결과(PR · 파일 · 기록)와 내가 한 지시를 읽고 감사해 — 실무 코드는 직접 고치지 마.
빠진 결정, 흐린 지시, 습관처럼 한 승인도 짚어 줘.
```

**런타임에 따라 두 길이다.**

| | 데스크톱 앱(Code 탭) | CLI 만 |
|---|---|---|
| 실무 세션 띄우기 | 거버너가 앱의 세션 도구로 하위 세션을 띄운다(내가 «새 세션으로 해줘» 라고 하면 된다) | 실무마다 **터미널 하나**. 같은 레포에서 브랜치가 다르면 `git worktree add ../<이름> -b <브랜치>` 로 폴더를 나눈다 |
| 거버너가 진행을 아는 법 | 하위 세션 턴이 끝날 때마다 알림이 온다 · 전사본을 읽는다 | 알림이 없다. **공유 기록**(아래 세션 장부)을 읽는다. 전사본은 `~/.claude/projects/<작업 폴더 경로를 - 로 이은 이름>/<세션 id>.jsonl` |
| 거버너 ↔ 실무 세션 대화 | 세션 간 메시지 | 내가 옮겨 준다, 또는 장부의 `note` 줄 |

- **실무 세션을 열 때 이렇게 일러 둔다**(CLI 면 필수). 실무 폴더가 FH 클론이 아니면 스크립트가 거기 없으니 FH 클론의 절대경로를 준다:

```
너는 실무 세션 work-a 고, 작업 이름은 login-fix 야. 단계가 바뀔 때마다(시작 · 막힘 · PR 열림 · 끝) 이 명령으로 한 줄씩 남겨:
bash <FH 클론 절대경로>/scripts/session_ledger_write.sh --session work-a --task login-fix --kind board|landing --state <상태> [--evidence "pr=#번호"]
```

  거버너에게는 띄운 실무 세션 이름 목록을 알려 준다(아래 `--expect` 에 그대로 쓴다).
- 🟥 **장부의 `done` 줄은 주장이지 증거가 아니다.** 감독 거버너는 그 줄이 가리키는 PR · 커밋 · 파일을 직접 연다.
  안 열고 «다 됐다» 고 전하면 감독이 아니라 중계다.

### 이어가기 — 개인 저장소 없이 쓰는 기록 넷

| 무엇을 이어야 하나 | 수단 | 어디 |
|---|---|---|
| 내가 미리 준 허락(상시 요청) | 위 세 칸 | 내 `CLAUDE.local.md` |
| 세션들이 어디까지 왔나 | 세션 장부 — `scripts/session_ledger_write.sh` 로 쓰고 `scripts/session_ledger_read.py` 로 읽는다 | 기본 `tracks/_meta/session_ledger/ledger.tsv`(워크트리에서도 본 체크아웃 한 파일) |
| 밤사이(내가 없는 동안) 무엇이 됐나 | 아침 보고 파일 — 형식 강제 없음. 칸 넷을 권한다: 머지된 것 · PR 에서 멈춘 것 · 내게 묻는 결정 · 못 잰 것 | 예: `tracks/_meta/morning_report_<날짜>.md` |
| 다음 세션이 어디서 시작하나 | FH 클론에서 연 세션의 마감(«마무리» 라고 말하면 된다)이 세션 카드를 갱신한다 | `tracks/_meta/reference_next_session_starter.md` |

세션 장부 예:

```bash
# 실무 세션이 쓴다 (세션 이름 · 작업 이름은 내가 정한다)
bash scripts/session_ledger_write.sh --session work-a --task login-fix --kind board --state in_progress --text "시작"
bash scripts/session_ledger_write.sh --session work-a --task login-fix --kind landing --state pr_open --evidence "pr=#12"

# 거버너가 읽는다 — --expect 에 띄운 세션을 다 적어라. 한 줄도 안 쓴 세션은 NOT-WRITTEN 으로 뜬다(종료코드 6).
# 장부 파일이 아직 없으면 종료코드 4 · 손상된 줄이 있으면 3 (여럿이면 4 → 3 → 6 순)
python3 scripts/session_ledger_read.py --expect work-a,work-b
```

- 상태 값은 닫혀 있다: `board` = planned · in_progress · blocked · done · abandoned / `landing` = pr_open · merged ·
  committed · file_written · unmeasured / `note` = info · finding · risk. `done` 과 `landing` 은 `pr=` · `commit=` ·
  `head=` · `path=` 중 하나가 있어야 써진다.
- 🟥 **FH 클론 밖의 내 프로젝트에서 쓰면** 그 레포의 `tracks/` 가 gitignored 가 아닐 수 있다. 모든 터미널에
  `export FH_SESSION_LEDGER=~/.fh-ledger/ledger.tsv` 처럼 레포 밖 한 경로를 지정해라(폴더는 먼저 만든다).
- 이 두 스크립트와 아래 판정기는 **클론에만 있다** — npm 패키지에는 아직 안 싣는다(시범 중). 플러그인만 깔았으면
  장부 대신 공유 파일 하나에 손으로 한 줄씩 적어도 같은 역할을 한다.

**맥락이 차기 전에 착지시키기** — 하위 세션이 자동 압축 직전까지 가면 앞 결정이 흐려진다. 절차:
`knowledge/shared/harness-core/governor_landing_before_compact.md`. 데스크톱 앱에서는 거버너가 하위 세션의 사용량을
읽어 판정한다. CLI 에서는 그 문서에 없는 대안이다(판정기 레인은 퍼센트 값만 시험한다 — `/context` 가 보여 주는 값과 같은 뜻인지는 아직 대조 안 했다):
그 세션에서 `/context` 로 맥락 사용 퍼센트를 보고 `python3 scripts/governor_landing_check.py --percent <값>`.
`OK`(0) 는 그대로 · `LAND`(1) 면 그 세션에 «지금 단위 마무리하고 인계 메모를 파일로 남겨» · `LATE`(3) 면 이미 늦었으니 인계 메모 착지부터 ·
`2` 는 입력 오류(«여유 있음» 이 아니다). 압축(`/compact`)은 사람이 친다.
