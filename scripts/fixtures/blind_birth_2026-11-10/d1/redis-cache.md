# Redis 캐시로 API 응답 시간 줄이기

이 글은 캐시를 처음 써 보는 입문 개발자를 위한 글이다.

## 왜 캐시인가

우리 팀의 상품 조회 API는 평균 800ms가 걸렸다. 조회 요청은 DB에 의해 매번 수행되어지고 있었고, 그것은 불필요한 부하를 가지고 있었다.
업계 평균 캐시 적중률은 85%다. 그러니 캐시를 붙이면 대부분의 요청이 DB까지 가지 않는다.

## 적용

TTL은 다들 아시겠지만 적당히 잡으면 된다. 우리는 LFU 기반 eviction과 write-behind 패턴을 섞어서 썼고, 키 스페이스 노티피케이션으로 무효화를 처리했다.

참고로 Redis 7.2부터 기본 maxmemory-policy가 allkeys-lru로 바뀌었기 때문에 따로 설정할 필요가 없다.

## 결과

캐시를 붙이자 상품 조회 API의 응답 시간이 90% 줄었다. 따라서 모든 API에 캐시를 붙여야 한다.
