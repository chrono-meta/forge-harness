# TODO CLI 오케스트레이터

**실행 모드:** 서브에이전트 위임(순차). 두 단계가 서로 대화할 필요 없이 파일 보고서로 전달되므로 가장 단순한 모드를 쓴다.

## 0단계: 맥락 확인
- `_workspace/`가 없으면 처음부터 실행한다.
- 있고 일부 수정 요청이면 해당 단계만 다시 실행한다(예: "QA만 다시" → 2단계).
- 있고 새 작업이면 `_workspace_{타임스탬프}/`로 옮긴 뒤 새로 시작한다.

## 1단계: 구현
`Agent(subagent_type: "todo-developer")`에 요구사항을 전달한다. 결과: 코드 변경과 `_workspace/01_developer_report.md`.

## 2단계: 검증
`Agent(subagent_type: "todo-qa")`에 보고서 경로를 전달한다. 결과: `_workspace/02_qa_report.md`.

## 3단계: 수정 루프
QA가 결함을 보고하면 개발자를 다시 호출해 QA 보고서를 반영하게 하고 2단계를 반복한다. 최대 2회. 그래도 남으면 남은 결함을 사용자에게 그대로 보고한다.

## 4단계: 보고
변경 요약, 테스트 결과, 남은 문제를 사용자에게 전달한다. `_workspace/`는 남긴다.

## 오류 처리
- 에이전트 실패는 1회 재시도하고, 또 실패하면 누락 사실을 보고에 적는다.
- 한도 소진·권한 거부는 재시도하지 않고 부분 산출물을 확인해 보고한다.

## 테스트 시나리오
- 정상: "`remove <번호>` 명령 추가" → 개발자가 구현+테스트, QA가 pytest와 경계 입력 통과 확인, 결함 0건으로 보고.
- 오류: QA가 `remove 99`의 트레이스백을 발견 → 개발자 재호출로 범위 검사 추가 → QA 재검증. 2회 후에도 실패하면 결함을 그대로 보고.
