# 주간 회의록 요약 오케스트레이터

**실행 모드:** 서브에이전트 위임(순차). 단계가 세 개뿐이고 에이전트끼리 대화할 필요가 없으며, 단계 사이는 파일로 넘긴다.

## 0단계: 맥락 확인
- 사용자가 회의록 위치를 말했으면 그 경로를 쓴다. 말하지 않았으면 `meetings/`, `notes/`, `회의록/` 순으로 찾고, 없으면 사용자에게 묻는다. 레포의 `todo/` 코드는 대상이 아니다.
- 요약 저장 경로를 지정받지 않았으면 `summaries/weekly_YYYY-MM-DD.md`(주 마지막 회의 날짜)를 기본값으로 쓴다.
- `_workspace/`가 있을 때:
  - 일부 수정 요청 → 해당 단계만 다시 실행한다.
  - 새 회의록 입력 → `_workspace_YYYYMMDD_HHMM/`으로 옮기고 새로 시작한다.
- 없으면 처음부터 실행한다.

## 1단계: 정리
`Agent(subagent_type: "note-organizer")`에 회의록 경로 목록을 전달한다. 결과: `_workspace/01_organizer_notes.md`.

## 2단계: 요약 작성
`Agent(subagent_type: "summary-writer")`. 결과: `_workspace/02_writer_summary.md`.

## 3단계: 검토와 보완
`Agent(subagent_type: "summary-reviewer")`에 원본 경로와 초안을 전달한다.
- 보고서가 "통과"면 초안을 최종 경로로 복사한다.
- 문제가 있으면 `summary-writer`를 다시 호출해 지적 사항만 고치게 하고, 검토를 한 번 더 한다. 그래도 남으면 남은 문제를 요약 끝에 `[확인 필요]`로 적고 사용자에게 알린다. 무한 반복하지 않는다.

## 4단계: 보고
최종 파일 경로, 처리한 회의록 수, 누락 파일, `[확인 필요]` 항목을 사용자에게 알린다. `_workspace/`는 남긴다.

## 오류 처리
- 에이전트 실패는 한 번 재시도한다. 또 실패하면 그 결과 없이 진행하고 누락 사실을 보고한다. 권한 거부 같은 재시도해도 같은 실패는 재시도하지 않는다.
- 원본끼리 내용이 충돌하면 지우지 말고 양쪽을 출처와 함께 남긴다.

## 테스트 시나리오
- **정상:** `meetings/`에 회의록 3개 → 정리본, 초안, "통과" 보고서, `summaries/weekly_*.md`가 생긴다.
- **오류:** 회의록 하나가 비어 있거나 읽을 수 없음 → 정리본 맨 위 "누락"에 기록되고, 최종 보고에 누락 파일이 언급된다.
- **후속:** "액션 아이템 표만 다시" → 2~3단계만 재실행한다.
