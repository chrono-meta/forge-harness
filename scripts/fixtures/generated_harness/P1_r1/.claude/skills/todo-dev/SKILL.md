# TODO CLI 개발 오케스트레이터

**실행 모드:** 서브에이전트 위임. 구현 → 검증 → (필요 시) 수정의 순차 흐름이고 반복은 최대 2회라 워크플로가 필요 없다.

## 0단계: 맥락 확인
- `_workspace/qa_report.md`가 있고 사용자가 일부만 고쳐 달라고 하면 해당 단계만 실행한다.
- 새 요청이면 기존 `_workspace/`를 `_workspace_{타임스탬프}/`로 옮기고 시작한다.

## 1단계: 구현
`Agent(subagent_type: "todo-developer")`에 요청 내용, 대상 파일, 지켜야 할 계약(아래)을 전달한다. 작은 변경이라도 테스트를 포함하게 한다.

## 2단계: 검증
`Agent(subagent_type: "todo-qa")`에 변경 파일 목록과 요청 내용을 전달한다. QA는 `_workspace/qa_report.md`를 쓴다. 구현자와 같은 맥락을 공유하지 않아야 독립 검증이 되므로 새 에이전트로 실행한다.

## 3단계: 수정 반복
보고서에 이번 요청과 관련된 결함이 있으면 `todo-developer`에 보고서 경로를 주고 고치게 한 뒤 QA를 다시 실행한다. 최대 2회 반복하고, 그래도 남으면 남은 결함을 사용자에게 그대로 보고한다. 요청 범위 밖의 기존 결함은 고치지 말고 보고서에 "범위 밖"으로 알린다.

## 지켜야 할 계약
- 저장소: `TODO_DB` 환경변수(기본 `todo.json`)의 JSON 배열, 항목은 `{"t": 제목, "done": bool}`
- 명령: `add <제목>`, `done <번호>`, `list` (번호는 0부터)
- 표준 라이브러리만 사용

## 오류 처리
- 에이전트 실패는 한 번 재시도한다. 재시도해도 실패하면 해당 단계 없이 진행하고 최종 보고에 누락을 적는다.
- 권한 거부·한도 소진은 재시도하지 않고 사용자에게 알린다.

## 데이터 전달
코드는 저장소에 직접 반영, 검증 결과는 `_workspace/qa_report.md` 파일로 전달한다.

## 테스트 시나리오
- **정상:** "완료된 항목만 보는 `list --done` 추가해줘" → developer가 구현+테스트 → QA가 통과 확인 → 요약 보고.
- **오류:** QA가 `done 99`에서 IndexError를 재현하면 → 요청 관련 결함일 때만 수정 반복, 아니면 "범위 밖"으로 보고.
