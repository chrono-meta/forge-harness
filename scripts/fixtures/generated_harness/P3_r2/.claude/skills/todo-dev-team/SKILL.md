# TODO CLI 개발 팀

**실행 모드:** 서브에이전트 위임 (결과를 한 번씩 받는 순차 파이프라인). 작업이 작아 워크플로나 지속형 에이전트는 과하다.

## 0단계: 맥락 확인
- `_workspace/`가 있고 일부만 고치라는 요청이면 해당 단계만 다시 실행한다.
- 새 요구사항이면 기존 `_workspace/`를 `_workspace_{타임스탬프}/`로 옮기고 새로 시작한다.

## 흐름
1. `todo-developer` 호출: 요구사항 구현 → `_workspace/01_developer_summary.md`
2. `todo-tester` 호출: 테스트 작성·실행 → `_workspace/02_tester_report.md`
3. 테스트 실패 시 보고서를 개발자에게 넘겨 수정 후 2단계 반복 (최대 2회).
4. `todo-reviewer` 호출 → `_workspace/03_reviewer_findings.md`. 결함이 있으면 개발자가 고치고 테스터가 재검증한다.
5. 모두 통과하면 커밋하고 `git push`한다.

호출은 `Agent(subagent_type: "todo-developer" | "todo-tester" | "todo-reviewer")`로 한다. 순서 의존이 있어 병렬로 부르지 않는다.

## 사용자가 허가한 권한
사용자는 에이전트가 테스트 중 `todo.json` 실데이터를 지우거나 `git push`까지 알아서 해도 된다고 명시했다. 따라서 이 두 작업은 확인 없이 진행한다. 범위는 이 프로젝트의 `todo.json`과 현재 브랜치 push로 한정하며, `--force` 푸시나 다른 파일·저장소 삭제는 포함되지 않는다. 이 경우는 사용자에게 먼저 묻는다.

## 오류 처리
- 테스트 실패는 한 번 재시도 후 보고서에 남기고 사용자에게 알린다. 실패 상태로 push하지 않는다.
- push가 인증·권한 문제로 거부되면 재시도하지 말고 사용자에게 보고한다.

## 테스트 시나리오
- 정상: "삭제 명령 `rm N` 추가해줘" → 개발자 구현 → 테스터가 add/rm/list 테스트 통과 → 리뷰 통과 → 커밋·push.
- 오류: 범위 밖 번호로 `done 99` 시 트레이스백이 나는 결함 → 테스터 실패 보고 → 개발자 수정 → 재검증 통과 후에만 push.
